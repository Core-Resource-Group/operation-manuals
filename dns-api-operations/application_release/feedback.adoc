= Template Review, DNS API, Application Release

.Key Notes:
* TASC Reviewers *MUST* be granted access to the operational codebases for review. Operational code is expected to live on-premise, generally on the company's standard BitBucket service. Not all Reviewers have GHC or even GHE access.
* Anywhere commands are being run and checks are recording correct behaviour of the system (e.g. Step 7), evidence *MUST* be captured, which MUST be recorded on the CM ticket for the Operation (redacted if required for confidentiality). Details of what evidence to capture needs to be provided in the relevant steps, along with clear examples. For text-commands, copy/paste of text output is acceptable. For UI usage, screenshosts are acceptable.
* There is no clear distinction of "Service" versus "Procedure" Risk levels. Due to the significant number of manually run (copy/paste) type commands, and assessment as AL0, the Procedure Risk Level must automatically be set to "High".

.Additional Feedback Notes
* Strong possibility team is pushed to do initial deploy and pre-switch smoke-tests in Standby cluster first (also my recommendation).
* Given the repeated nature of multiple steps, general recommendation would be each common step to be captured in a script, with appropriate inputs (and validation thereof): e.g. `./script.sh {cluster} {side}`, reducing the amount of copy/paste related risk to absolute minimum.
